# zeroPlayer 2.0 — 기획 개요

## 1. 한 줄 정의

지금 상황에 맞는 인터넷 라디오와 팟캐스트를 골라주고, 타이머로 끄고 알람으로 켜는 플레이어다.

앱의 본체는 음원이 아니라 **켜고 끄는 방식**이다. 취침·운전·공부·작업·기상이라는 다섯 가지 상황이 있고, 각 상황마다 무엇을 틀고 언제 끌지가 정해져 있다. 음원은 갈아끼울 수 있는 부품이다.

## 2. 1.x 에서 무엇이 바뀌는가

| 항목 | 1.7 | 2.0 |
| --- | --- | --- |
| 공개 기능 | 유튜브 재생목록 재생 | 인터넷 라디오 + 팟캐스트 + 상황 큐레이션 |
| 히든 기능 | 한국 지상파 라디오 14개 | 유지. 버전 라벨 40회 탭 방식은 재설계 |
| 채널 데이터 | Swift 배열에 하드코딩 | 프록시가 JSON 으로 제공 |
| 방송사 페이지 파싱 | 앱 안에서 Kanna 로 파싱 | 프록시가 담당 |
| 알람 | 로컬 알림 + 앱이 살아 있어야 재생 | 서버 푸시 + 로컬 백업, 탭하면 재생 |
| 수익 | 없음 | AdMob 배너 (재생 화면 제외). 보상형은 쓰지 않는다 |
| UI | Storyboard + UIKit | SwiftUI |
| 저장 | Documents 폴더의 JSON 2개 | SwiftData |
| 최소 iOS | 12.4 | **17.0** |

유튜브 재생목록은 **제거한다**. 화면을 끈 채 소리만 쓰는 방식이 YouTube API Services Developer Policies III.I.9(백그라운드 플레이어 금지)와 III.I.7(오디오·비디오 분리 금지)에 어긋난다. 광고를 붙이면 III.G.1 의 광고 조항까지 함께 발동한다. 공개 기능 자리를 라디오와 팟캐스트가 채우므로 기능이 겹치지도 않는다.

## 3. 공개 기능과 히든 기능

```
공개
 ├ 인터넷 라디오    radio-browser 데이터, 전 세계
 ├ 팟캐스트         Podcast Index 데이터
 └ 상황 큐레이션    둘을 섞어 추천
히든
 └ 한국 지상파 라디오 (KBS·MBC·SBS·CBS·TBS·AFN) + 편성표
공통
 └ 상황 프리셋 · 자동 종료 타이머 · 알람 · 청취 기록
```

히든 기능은 광고 화면과 완전히 분리한다. 히든 채널을 재생하는 동안에는 배너를 내린다.

## 4. 락인 설계

기능은 흉내 낼 수 있지만 사용자가 쌓아둔 것은 옮길 수 없다. 2.0 의 락인은 네 가지다.

**상황 프리셋.** "취침 = 이 채널 + 45분 타이머 + 페이드아웃", "출근 = 뉴스 팟캐스트 30분 뒤 음악 라디오". 한 번 탭하면 전부 적용된다. 몇 달 쓰면 자기에게 맞춰진 조합이 쌓인다.

**청취 기록.** 사용자가 입력할 것이 없다. 무엇을 언제 얼마나 들었는지 저절로 남고, 월별 리포트가 된다.

**개인화된 추천.** 오래 들은 채널은 올라가고 30초 안에 넘긴 채널은 내려간다. 두 달 치 취향이 쌓이면 다른 앱에서 처음부터 다시 만들어야 한다.

**알람.** 매일 아침 이 앱이 깨운다. 습관에 묶이면 지우기 어렵다.

앞의 두 개가 특히 중요하다. 사용자가 노력해서 채우는 기록은 대부분 2주 안에 끊긴다. 저절로 쌓이는 기록만 남는다.

## 5. 만들지 않는 것

- **유튜브 관련 기능 전부.** 재생목록, 숏츠 뷰어, YouTube Music. 약관 근거는 `05-ads-policy.md`.
- **기기 안의 음악 파일 재생.** 파일을 넣어야 시작되니 진입이 무겁고, 큐레이션 대상도 되지 않는다.
- **Apple Music·Spotify 연동.** MusicKit 은 광고를 금지하고, Spotify 는 2024-11-27 부로 신규 앱의 추천 엔드포인트를 닫았다.
- **소셜 기능.** 공유 프리셋, 같이 듣기 등은 초기 사용자 수가 받쳐줘야 작동한다. 2.0 범위 밖이다.
- **CarPlay.** 운전 상황이 있지만 CarPlay 오디오 앱은 애플 엔타이틀먼트 승인이 따로 필요하다. 2.1 이후에 검토한다.
- **직접 녹음·업로드.**
