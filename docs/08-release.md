# 출시 준비

App Store 에 2.0 을 올리기 전에 채워야 하는 것을 모은다. 코드가 아니라 콘솔에서 하는 일이 대부분이다.

## 1. App Store Connect 에 넣는 값

버전 정보에 딸린 값이라 새 버전을 제출해야 바뀐다. 1.7 은 이 칸이 전부 비어 있다.

| 칸 | 값 |
| --- | --- |
| 마케팅 URL | `https://zeroplayer.zerolive.co.kr` |
| 지원 URL | `https://zeroplayer.zerolive.co.kr/support` |
| 개인정보처리방침 URL | `https://zeroplayer.zerolive.co.kr/privacy` |

**마케팅 URL 이 AdMob 앱 인증을 푼다.** AdMob 은 App Store 앱 페이지의 '개발자 웹사이트'
를 읽고 그 도메인의 루트에서 `/app-ads.txt` 를 찾는다. 그 값이 곧 마케팅 URL 이다.
지금 비어 있어서 크롤할 곳이 없고, 그래서 인증이 '찾을 수 없음' 에 멈춰 있다.
2.0 이 스토어에 반영된 뒤 AdMob 에서 다시 확인을 누르면 풀린다.

## 2. App Privacy 표기

### 2.1 앱이 직접 보내는 것

| 항목 | 분류 | 쓰는 곳 | 사용자에 연결 | 추적 |
| --- | --- | --- | --- | --- |
| 설치 UUID | 식별자 → 사용자 ID | 알람 등록, 히든 해제, 남용 차단 | 예 | 아니요 |
| APNs 기기 토큰 | 식별자 → 기기 ID | 알람 푸시 발송 | 예 | 아니요 |
| 알람 설정(시각·요일·소스) | 사용자 콘텐츠 → 기타 | 앱 기능 | 예 | 아니요 |
| 재생 실패 신고(방송국 번호) | 진단 → 기타 | 죽은 방송국 걸러내기 | 아니요 | 아니요 |

설치 UUID 는 기기 식별자가 아니라 앱이 처음 실행될 때 만들어 키체인에 넣는 값이다.
앱을 지웠다 깔아도 키체인에 남을 수 있어 **'사용자 ID' 로 표기한다.**

### 2.2 기기에만 있고 서버로 보내지 않는 것

청취 기록, 즐겨찾기, 프리셋, 이어듣기 위치, 추천 품질 지표. 전부 SwiftData 에만 있다.
**App Privacy 에 적지 않는다** — 수집하지 않기 때문이다. 개인정보처리방침에는 명시한다.

### 2.3 AdMob 이 가져가는 것

광고 SDK 가 수집하는 항목은 앱이 정하는 것이 아니다. 제출 직전에 구글이 공개한
'AdMob SDK 데이터 공개' 문서를 그대로 옮긴다. 2026-09 기준으로 적어도 다음이 들어간다.

- 식별자 → 기기 ID (IDFA·IDFV). **추적 목적**
- 사용 데이터 → 제품 상호작용, 광고 데이터
- 위치 → 대략적인 위치
- 진단 → 크래시·성능 데이터

추적 목적이 하나라도 있으면 ATT 허가창이 필요하다. 문구는 `project.yml` 의
`NSUserTrackingUsageDescription` 에 있다.

## 3. 심사에서 미리 말해 둘 것

**히든 라디오를 심사 메모에 반드시 적는다.** 애플 심사 지침 2.3.1 은 숨겨진 기능과
문서화되지 않은 기능을 금지한다. 여는 방법을 심사 메모에 적어 두면 '숨긴 기능' 이 아니라
'설명된 기능' 이 된다. 적지 않고 발견되면 반려 사유가 된다.

> 설정 화면의 버전 번호를 12번 누르면 탐색 탭에 '지상파' 갈래가 나타납니다.
> 한국 지상파 라디오를 듣는 기능이며, 1.7 사용자가 쓰던 기능을 이어받은 것입니다.

함께 적을 것.

- **백그라운드 오디오** — 인터넷 라디오와 팟캐스트를 화면을 끈 채 듣는 앱이다.
- **Time Sensitive Notifications** — 알람 기능이라 집중 모드에서도 떠야 한다.
- **알람은 탭해야 소리가 난다** — iOS 제약을 인정한 설계다(`docs/01-features.md` 5.1).
  시계 앱처럼 저절로 울리지 않는다는 점을 적어 둔다.
- **방송 콘텐츠** — 스트림을 그대로 재생하고 방송국 광고를 지우지 않는다. 방송국 정보와
  홈페이지 링크를 표시한다(`docs/05-ads-policy.md` 4번).

## 4. AdMob — 제출 전에 광고 단위를 먼저 만든다

**스토어 게시를 기다릴 필요가 없다.** AdMob 에서 앱을 추가할 때 "앱이 지원되는 스토어에
등록되어 있나요?" 에 **아니요** 를 고르면 스토어에 없는 앱도 만들 수 있고, 앱 ID 와 광고
단위 ID 가 바로 나온다. 나중에 2.0 이 게시되면 그 앱을 스토어 항목에 연결한다.

순서를 이렇게 잡는 이유는 하나다. 테스트 ID 로 제출하면 출시 첫날부터 수익이 0 이고,
실제 ID 를 넣으려고 빌드를 한 번 더 올려 심사를 또 받아야 한다.

1. 앱을 등록한다. 번들 ID `com.zerolive.cloudRadioN`, 플랫폼 iOS.
   1.7 이 이미 스토어에 있으니 '스토어에 등록되어 있나요' 에 **예** 를 고르고
   zeroPlayer(id1610259595)를 찾아 연결한다. 아니요로 만들면 리포트가 스토어 데이터와 따로 논다.
2. 앱 ID(`ca-app-pub-…~…`)를 `Configs/Release.xcconfig` 의 `ZP_ADMOB_APP_ID` 에 넣는다.
3. 배너 광고 단위를 넷 만든다 — 추천·탐색·프리셋·기록. 같은 파일의 `ZP_ADMOB_BANNER_*` 에 넣는다.
   한 자리에 하나씩 둬야 어느 화면이 버는지 보인다.

**1~3 은 끝났다.** 앱 ID `ca-app-pub-4410880415888380~5460302040` 과 배너 넷이
`Configs/Release.xcconfig` 에 들어가 있고, 배포 빌드와 아카이브로 확인했다.
4. **동의 메시지를 한국어로 만든다.** 지금 쓰는 구글 테스트 계정에는 영어 ATT 사전 안내가
   모든 지역에 걸려 있어 앱을 열자마자 영어 창이 뜬다. 실제 계정에서는 EEA·영국에만
   동의창이 필요하고, 한국 사용자에게는 아무 창도 뜨지 않는다.
5. **내 기기를 테스트 기기로 등록한다.** 실제 ID 로 빌드한 뒤 내가 내 광고를 누르면
   무효 트래픽이 되어 계정이 막힐 수 있다. 기기 ID 는 앱을 실행하면 로그에 찍힌다
   (`To get test ads on this device, set: …testDeviceIdentifiers = [ "…" ]`).

**AdMob 값은 빌드 설정에 있고 커밋한다.** 비밀이 아니라 Info.plist 에 그대로 박히는
값이고, 저장소를 새로 받은 사람의 배포 빌드도 실제 광고로 나가야 하기 때문이다.
개발 빌드는 `Configs/Debug.xcconfig` 의 구글 테스트 ID 를 쓴다 — 개발하면서 실제
광고를 누르면 무효 트래픽이 된다.

테스트 ID 가 남은 채로는 **아카이브가 되지 않는다.** `project.yml` 의 'AdMob ID 확인'
단계가 `ACTION=install` 일 때만 값을 보고 막는다. 평소 Release 빌드는 그대로 된다.
설정 화면의 광고 줄에 '테스트 단위' 표시가 남아 있는지로도 확인할 수 있다.

**app-ads.txt 인증은 제출을 막지 않는다.** 파일은 광고 재고를 사칭당하지 않게 막는
장치이지 광고를 켜는 조건이 아니다. 인증 전에도 배너는 나가고, 확인된 인벤토리만 사는
일부 광고주가 빠지는 정도다. 2.0 이 게시되고 마케팅 URL 이 스토어에 반영된 뒤
AdMob 에서 다시 확인을 누르면 풀린다(1절).

## 5. 코드 쪽에서 끝낸 것

제출 전에 코드에 있어야 하는 것들이다. 모두 들어갔고 릴리스 빌드 산출물에서 확인했다.

| 항목 | 어디에 |
| --- | --- |
| 개인정보 매니페스트 | `Sources/Resources/PrivacyInfo.xcprivacy` → 번들 루트 |
| 추적 허가 문구(한국어·영어) | `Sources/Resources/{ko,en}.lproj/InfoPlist.strings` |
| SKAdNetwork 52개 | `project.yml` 의 `SKAdNetworkItems` |
| 배포용 APNs 엔타이틀먼트 | `Sources/App/zeroPlayerRelease.entitlements` (`production`) |
| 암호화 신고 | `ITSAppUsesNonExemptEncryption: false` (HTTPS 만 쓴다) |
| 지원 언어 | `CFBundleLocalizations: ko, en` |

**개인정보 매니페스트가 없으면 업로드가 막힌다.** `@AppStorage` 와 재생 속도 기억에
UserDefaults 를 쓰는데 사유를 안 밝히면 애플이 `ITMS-91053` 로 돌려보낸다.
사유는 `CA92.1`(이 앱이 저장한 값을 이 앱이 읽음)이다. 앞으로 사유를 밝혀야 하는 API
(파일 타임스탬프·디스크 여유·부팅 시각·활성 키보드)를 새로 쓰면 이 파일에 한 줄 더한다.

**아이폰과 아이패드를 둘 다 지원한다.** 1.7 이 아이패드를 지원했으므로 2.0 에서
줄일 수 없다. `TARGETED_DEVICE_FAMILY: "1"` 로 좁혀 올렸다가 업로드 검증이
`This bundle does not support one or more of the devices supported by the previous app
version`(QA1623) 으로 떨어졌다. 지금은 `"1,2"` 다. 아이패드 스크린샷도 함께 올린다.
아이폰 전용으로 내려면 번들 ID 를 바꿔 새 앱으로 내는 수밖에 없는데, 그러면 1.7
사용자가 업데이트를 못 받고 순위·리뷰가 0 에서 다시 시작한다.

## 6. 앱 쪽 점검

- [ ] 실기기에서 배너가 네 화면에 뜨고, 재생 화면·미니 플레이어·지상파·알람 직후에는 안 뜬다
- [ ] ATT 허가창이 한 번만 뜨고, 거부해도 배너가 계속 나온다
- [ ] 배포 빌드로 깔면 설정 화면의 '테스트 단위' 표시가 사라진다 (개발 빌드에는 그대로 남는다)
- [ ] 1.7 에서 업데이트했을 때 알람·히든 해제·채널 목록이 그대로 옮겨진다
- [ ] 유튜브 안내가 한 번만 뜬다
- [ ] 글자 크기를 가장 크게 해도 화면이 깨지지 않는다
- [ ] VoiceOver 로 재생·일시정지·프리셋 실행을 할 수 있다
