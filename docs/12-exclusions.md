# 12. 그만 듣기 — 자동 선택에서 방송을 뺀다

기상 알람을 자동 선택으로 걸어 두었는데 마음에 안 드는 방송이 나왔다. 직접 방송국을
지정하고 싶지는 않다 — 그러면 자동 선택을 쓰는 뜻이 없다. 싫은 것만 빼고 나머지는 앱이
고르게 하는 자리가 필요했다.

## 12.1 두 장치로 나눈다

하나만 두면 반쪽이다. 역할이 다르다.

| | 무엇 | 언제 듣는가 |
| --- | --- | --- |
| **자동** | 30초 안에 넘기면 순위가 내려간다 | 아무것도 누르지 않아도 된다. 평소에 이것이 일한다 |
| **손으로** | 재생 화면의 '그만 듣기' | "이건 진짜 싫다" 일 때의 탈출구 |

### 자동 쪽은 버그를 고친 것이다

장치는 처음부터 있었다. `Personalizer` 에 "30초 안에 넘긴 횟수" 벌점이 있다. 그런데
**알람 자동 선택만 그 계산을 거치지 않았다.** 서버가 준 1위를 그대로 울렸다
(`AlarmPlaybackBridge.resolve` 가 `set.items.first` 를 그냥 썼다). 프리셋은 거쳤는데
알람만 빠져 있었으니, 넘겨도 다음 아침에 또 나온 것이 당연했다.

벌점 자체도 약했다. 점수가 `목록 개수 − 순위` 에서 출발하므로 20개 목록에서 1위와
꼴찌 차이가 19점인데 넘김 한 번이 1.2점이었다. **1위를 밀어내려면 열여섯 번 넘겨야 했다.**
지금은 목록 길이에 비례한다(`skipPenaltyRatio = 0.45`) — 한 번이면 중간쯤, 두 번이면
목록 밖이다.

### 손으로 빼는 쪽은 넘어가야 한다

'그만 듣기' 를 누르면 그 방송을 목록에 담고 **다음 순위 후보로 넘어간다.** 담기만 하고
계속 틀어 두면 사용자는 아무 일도 안 일어난 줄 안다.

넘어갈 후보가 없으면 멈춘다. 이것도 알려 준다 — 재생 화면에 한 줄이 몇 초 뜬다.

## 12.2 '삭제' 가 아니다

목록은 서버가 내려 주고 여섯 시간마다 갱신된다. 기기가 지울 수 있는 것이 아니다.
그래서 낱말을 **'그만 듣기'** 로 쓴다. '삭제' 라고 적으면 다시는 안 보인다고 기대하는데
탐색 탭에는 그대로 있으니 어긋난다.

**탐색 탭에서는 감추지 않는다.** 제외는 "앱이 알아서 고를 때 빼 달라" 는 뜻이고,
내가 직접 찾아 누르는 것을 막을 이유가 없다. 대신 줄에 `speaker.slash` 표시를 두어
왜 추천에 안 나오는지 알 수 있게 하고, 왼쪽으로 밀면 거기서도 넣고 뺄 수 있다.

걸러내는 자리는 **앱이 고르는 곳 전부**다.

| 자리 | 어떻게 |
| --- | --- |
| 추천 탭 | 화면에서 걸러낸다(`@Query` 로 반응한다) |
| 프리셋 자동 선택 | `PresetLauncher.candidates` 가 후보에서 뺀다 |
| 알람 자동 선택 (iOS 26+) | `AlarmPlaybackBridge.candidates` 가 후보에서 뺀다 |
| 알람 자동 선택 (iOS 25−) | **서버가** 뺀다. 아래 12.4 |
| 탐색 탭 | 빼지 않는다. 표시만 둔다 |

**프리셋이 지정한 방송국은 제외 대상이 아니다.** 직접 골라 걸어 둔 것을 자동으로 빼면
그 프리셋이 조용히 다른 방송을 튼다. 같은 이유로 서버의 지정 알람(`source_kind != 'auto'`)
도 걸러내지 않는다.

## 12.3 되돌릴 길을 먼저 보이게 둔다

되돌릴 수 있다는 것이 보이지 않으면 사용자가 '그만 듣기' 를 아예 안 누른다. 그래서
전부 비우는 단추 하나로 두지 않았다.

설정 → **그만 듣는 방송(개수)** 에 목록이 있다. 이름과 뺀 날짜를 보여 주고 줄마다
'되돌리기' 가 붙는다. 실수로 하나 뺀 것을 되돌리는 것이 훨씬 흔한 일이다. 모두
되돌리기는 그 아래에 둔다.

## 12.4 iOS 25 이하는 서버에도 맞춘다

여기서는 알람에 무엇을 틀지 **서버가** 고른다(`server/src/lib/alarmDispatch.ts` 의
`resolveSource`). 기기에만 두면 아침에 뺀 방송이 그대로 온다.

```
PUT /zp/v1/exclusions   {"stations": ["rb:...", ...]}
GET /zp/v1/exclusions
```

- **목록 전체를 덮어쓴다.** 하나씩 더하고 빼는 경로를 두지 않는다 — 기기와 서버가
  어긋났을 때 되맞출 길이 없어진다. 기기가 가진 것이 정답이다.
- 올라가는 것은 **방송국 번호뿐**이다. 무엇을 얼마나 들었는지는 여전히 가지 않는다.
- **iOS 26 이상은 올리지 않는다.** 앱이 직접 고르니 서버가 알 이유가 없다. AlarmKit
  권한을 받는 순간 앱이 빈 목록을 올려 서버 사본을 지운다 — 푸시 토큰을 지우는 것과
  같은 자리다(`ExcludedStore.dropServerCopyIfNeeded`).
- 못 올려도 기기 쪽은 곧바로 걸러낸다. 못 올린 것은 `needsSync` 로 표시해 두고 다음에
  앱을 열 때 밀어 넣는다.
- 그래도 **푸시를 받은 뒤 앱에서 한 번 더 막는다**(`RootView.startAlarm`). 올리지 못한
  채 아침이 올 수 있고, 그때 뺀 방송으로 깨우면 뺀 의미가 없다.

이 때문에 개인정보처리방침이 바뀌었다. 서버로 가는 값 목록에 제외한 방송국 번호가
들어간다 — 공언한 것과 실제가 어긋나면 안 되므로 랜딩의 방침 문서와 `llms.txt` 를
함께 고쳤다.

## 12.5 검토했지만 만들지 않은 것

| 안 | 왜 안 만들었는가 |
| --- | --- |
| 프리셋마다 따로 제외 목록 | 취침에서 싫은 방송이 기상에서 좋을 일은 드물다. 같은 것을 다섯 프리셋에 다섯 번 넣게 된다 |
| 자동 → '목록 보기' 에서 제외 | 그 목록은 시각·요일마다 다르다. 지금 보는 것이 내일 아침의 목록이 아닌데 '목록' 이라 부르면 고정으로 읽힌다. 나중에 넣는다면 **'지금이라면 이 방송들'** 처럼 그 순간의 후보라는 것이 드러나는 이름이어야 한다 |

## 12.6 구현된 곳

| 파일 | 하는 일 |
| --- | --- |
| `Sources/Core/Persistence/Models/ExcludedStation.swift` | 뺀 방송 한 줄. 번호·이름·날짜·서버 반영 여부 |
| `Sources/Core/Persistence/Store/ExcludedStore.swift` | 넣고 빼고 되돌린다. 서버와 맞추는 것도 여기 |
| `Sources/Core/Player/StationExcluding.swift` | 재생 코드가 SwiftData 를 모르게 하는 통로 |
| `Sources/Core/Player/AudioPlayerService.swift` | 후보 줄(`queue`)과 `excludeCurrentAndAdvance()` |
| `Sources/Features/Settings/ExcludedStationsView.swift` | 목록과 되돌리기 |
| `server/src/routes/exclusions.ts` | `PUT`·`GET /exclusions` 와 `excludedFor()` |
| `server/migrations/0011_exclusions.sql` | `excluded_stations` 표 |

**저장소는 앱에 하나만 둔다.** 화면이 쓸 때마다 새로 만들면 각자 다른 사본을 들고 있어서
설정에서 되돌린 것이 재생기 쪽에 반영되지 않는다. `@Observable` 로 두고 환경으로 내려보낸다.
